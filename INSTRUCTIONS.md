# How to Create and Build Codelabs

This repository provides an automated pipeline for authoring, compiling, and publishing interactive technical codelabs at [codelabs.kartikarora.me](https://codelabs.kartikarora.me).

Codelabs are authored in Markdown, compiled into interactive HTML using [Klaat](https://github.com/kartikarora/klaat), and bundled into a web portal via a Node.js manifest builder.

---

## 📋 Prerequisites & Tooling

### 1. Node.js
Ensure you have Node.js (v18+) installed to run the manifest and site compilation scripts:
```bash
node -v
```

### 2. Klaat CLI
[Klaat](https://github.com/kartikarora/klaat) converts structured Markdown into Google Codelab-style interactive tutorials.

Install via Homebrew:
```bash
brew tap kartikarora/klaat
brew install klaat
```
Or install snapshot builds:
```bash
brew tap kartikarora/klaat-snapshots
brew install klaat-snapshot
```

## 📁 Repository Structure

```text
├── source/                 # Markdown tutorials and source assets
│   └── <slug>/             # Each codelab lives in its own folder
│       ├── codelab.md      # Canonical Markdown source
│       └── images/         # Local images referenced in the codelab
├── codelabs/               # Compiled HTML codelabs generated by Klaat
├── dist/                   # Production distribution folder (static site)
├── generate-manifest.js    # Compiles dist/, copies codelabs, and outputs codelabs.json
├── index.html              # Landing portal template (Brand Design System)
└── wrangler.toml           # Cloudflare Pages / deployment config
```

## ✍️ Step-by-Step: Creating a New Codelab

### 1. Create the Codelab Directory
Create a folder inside `source/` named with your chosen slug (lowercase alphanumeric and hyphens):
```bash
mkdir -p source/my-new-codelab/images
```

### 2. Author `source/<slug>/codelab.md`
Create `source/<slug>/codelab.md`. The document must follow Klaat's required format:

#### Frontmatter
Start with YAML frontmatter at the top of the file:
```markdown
---
id: my-new-codelab
summary: A concise, single-sentence summary of the codelab.
categories: AI, Android, Web
environments: Web
status: Published
authors: Kartik Arora
feedback_link: https://github.com/kartikarora/codelabs/issues
tags: ai, gemini, agents
---
```

Key Frontmatter Fields:
- `id` *(required)*: Unique URL-safe slug matching the folder name.
- `summary` *(required)*: Short description used on landing cards and search indexes.
- `categories`: Comma-separated categories (e.g., `AI`, `Android`, `Web`, `Cloud`).
- `status`: `Published`, `Draft`, or `Deprecated`.
- `authors`: Author name(s).
- `tags`: Comma-separated search keywords.

#### Document Hierarchy
Structure the body using clear Markdown headings:
- **Title (H1)**: `# Codelab Title` (only one at top)
- **Steps (H2)**: `## Step Title`
- **Step Duration**: Place `Duration: <minutes>` on the very next line beneath each `## Step Title`.
- **Sub-sections (H3)**: `### Section Title`
- **Important**: Do **not** use horizontal rules (`---`) between steps.

#### Markdown Format Example

```markdown
---
id: my-new-codelab
summary: Learn how to build intelligent agents with Gemini.
categories: AI, Web
environments: Web
status: Published
authors: Kartik Arora
feedback_link: https://kartikarora.me
tags: ai, gemini, agents
---

# Building AI Agents with Gemini

## Overview & Prerequisites
Duration: 3

Welcome to this codelab! In this tutorial, you will learn how to design, test, and deploy intelligent agents.

### What You'll Learn
- How agent loops work
- Tool calling and MCP integration
- Production deployment best practices

## Environment Setup
Duration: 5

Before proceeding, ensure your development environment is ready.

```bash
npm install -g @google/genai
```

> Make sure your API key is exported as an environment variable before continuing. {.warning}

## Creating Your First Agent
Duration: 10

Create a file named `agent.ts`:

**agent.ts**
```typescript
import { GoogleGenAI } from '@google/genai';

const ai = new GoogleGenAI();
console.log("Agent initialized");
```

> You can inspect logs in your terminal output. {.special}

## Conclusion & Next Steps
Duration: 2

Congratulations! You have completed the codelab.
```

## 🎨 Klaat Content Formatting Syntax

### Info Boxes (Callouts)
- **Tip / Highlight Box**:
  ```markdown
  > Here is a useful tip or piece of context. {.special}
  ```
- **Warning / Alert Box**:
  ```markdown
  > Be careful! Changing this setting will delete data. {.warning}
  ```

### Code Blocks with Filenames
Add the filename in bold directly above the fenced code block:
```markdown
**index.js**
```javascript
console.log("Hello, world!");
```
```

For outer prompt text containing nested code blocks, use four backticks (` ```` `).

### Images
Store images under `source/<slug>/images/` and reference them relatively:
```markdown
![Architecture Diagram](images/architecture.png)
*Figure 1: High-level system architecture overview.*
```

### Interactive Surveys & Polls
```markdown
**How comfortable are you with this framework?**
- [ ] Novice
- [ ] Intermediate
- [ ] Expert
```

## ⚙️ Compiling & Publishing

### Step 1: Export to HTML with Klaat
Run `klaat export` (or `klaat-snapshot export`) targeting the `codelabs` directory:
```bash
klaat export -o codelabs source/my-new-codelab/codelab.md
```
*Alternatively, if using `klaat-snapshot`:*
```bash
klaat-snapshot export -o codelabs source/my-new-codelab/codelab.md
```
This generates the interactive HTML bundle inside `codelabs/my-new-codelab/`.

### Step 2: Rebuild the Distribution Bundle & Manifest
Run `generate-manifest.js` to index all codelabs, update `dist/codelabs.json`, update `llms.txt`, and assemble `dist/`:
```bash
node generate-manifest.js
```

### Step 3: Preview Locally
Start a local HTTP server pointing to `dist/`:
```bash
python3 -m http.server 8000 --directory dist
```
Open `http://localhost:8000` in your browser to verify:
1. The codelab appears on the landing portal card grid.
2. The interactive codelab renders correctly and step navigation works.
3. Category filters and search tags function as expected.

## 🚀 Deployment

The site is served using Cloudflare Pages / Workers configured in `wrangler.toml`. Once changes are committed and pushed to GitHub, the build pipeline automatically deploys the updated bundle.
